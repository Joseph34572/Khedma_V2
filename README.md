# تطبيق خدمة مرحلة إعدادي

تطبيق ويب لإدارة ومتابعة خدمة مرحلة إعدادي (أولى/تانية/تالتة إعدادي) في الكنيسة،
مبني بـ Next.js وSupabase (PostgreSQL)، بواجهة عربية بالكامل واتجاه من اليمين لليسار.

## حالة المشروع

تم بناء **المرحلة الأولى** بالكامل من خطة التطوير:
- قاعدة البيانات الكاملة بعلاقاتها وفهارسها وقيودها
- نظام صلاحيات حقيقي مطبَّق كسياسات RLS على مستوى قاعدة البيانات (وليس الواجهة فقط)
- تسجيل الدخول برقم الهاتف وكلمة المرور
- إدارة المستخدمين الكاملة (إضافة، تعديل، تعطيل، إعادة تفعيل، تغيير كلمة مرور)
- لوحة تحكم الإدارة بإحصائيات حقيقية
- جدول متابعة الخادم لأولاد مرحلته
- صفحة ملف الولد
- تسجيل حضور القداس (تسجيل ذاتي)
- سجل العمليات الحساسة
- حماية صريحة على مستوى الخادم لمسار الدخول الرئيسي (لا يمكن الوصول لأي
  محتوى بدون تسجيل دخول صالح)
- تحسين أداء: جلب الملف الشخصي وحالة الجلسة مرة واحدة فقط لكل طلب عبر دالة
  مشتركة مخزَّنة (`getCurrentProfile`) بدل استعلامات متكررة في كل تخطيط وصفحة

تم أيضًا بناء: الصلاة التفاعلية، قارئ الكتاب المقدس (مع استيراد المحتوى من
الإدارة والخدام)، حضور القداس ومدارس الأحد (يدويًا وبمسح رمز QR بالكاميرا)،
صندوق الندوة (مع إخفاء هوية حقيقي عبر عرض قاعدة بيانات مخصص)، والمسابقات
(أسئلة داخل التطبيق أو ملف يرفعه الخادم ويرفع الأولاد حلّه، مع تصحيح يدوي
للأسئلة النصية وملفات الإجابة)، ومركز إشعارات داخل التطبيق (إرسال واستقبال).

### لوحة متابعة الخادم (موسّعة)

لوحة الخادم الآن مفصولة إلى صفحتين: "الرئيسية" (ملخص سريع وروابط) و"أولادي"
(جدول المتابعة الأساسي)، وفق المواصفة التالية:
- جدول بعشرة أعمدة: الاسم، آخر نشاط صلاة، حالة صلاة اليوم، آخر قراءة للكتاب،
  حالة قراءة اليوم، آخر حضور قداس، آخر اعتراف (مقيّد)، آخر حضور مدارس الأحد،
  نشاط الأسبوع الحالي، نشاط الشهر الحالي.
- حالات مرئية بالرمز والنص معًا (✅ مكتمل / 🟡 لم يكتمل بعد / 🔴 متأخر / —
  لم يسجل) — لا اعتماد على اللون وحده.
- بحث بالاسم، وتصفية حسب حالة الصلاة/القراءة اليوم، مستوى النشاط، والفترة
  الزمنية، وترتيب قابل للتبديل من كل عمود.
- ملخص سريع أعلى الجدول (عدد الأولاد، صلّوا اليوم، قرأوا اليوم، حضروا القداس
  آخر 7 أيام، آخر حضور مدارس أحد).
- على الموبايل يبقى عمود الاسم ثابتًا مع تمرير أفقي لباقي الأعمدة (الجدول لا
  يتحول إلى كروت منفصلة).
- صفحة ملف الولد (بالضغط على اسمه) تعرض تبويبات: تاريخ الصلاة، قراءة الكتاب
  المقدس، القداسات، الاعتراف (مقيّد)، مدارس الأحد (مع اسم من سجّل الحضور)،
  المسابقات، صندوق الندوة، و"التاريخ الكامل" (Timeline زمني لكل الأنشطة).
- تواريخ الحضور (قداس/مدارس أحد) تُعرض بتاريخ الحدث الفعلي دائمًا، وليس بوقت
  تسجيله في النظام.

جميع هذه البيانات مبنية على Views تحترم RLS فعليًا (`security_invoker`)، وكل
تصفية حسب المرحلة مفروضة من قاعدة البيانات نفسها وليس من الواجهة فقط.

## التشغيل محليًا

### المتطلبات
- Node.js نسخة 20 أو أحدث
- حساب على [Supabase](https://supabase.com) (مجاني للبدء)

### 1) تثبيت الحزم

```bash
npm install
```

### 2) إنشاء مشروع Supabase

1. أنشئ مشروعًا جديدًا من لوحة تحكم Supabase.
2. من **Project Settings → API** انسخ:
   - `Project URL` → استخدمه كـ `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public key` → استخدمه كـ `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role key` → استخدمه كـ `SUPABASE_SERVICE_ROLE_KEY` (**سرّي جدًا، لا تشاركه أبدًا**)

### 3) إعداد متغيرات البيئة

```bash
cp .env.example .env.local
# ثم املأ القيم الثلاث داخل .env.local
```

### 4) تطبيق قاعدة البيانات

من **SQL Editor** داخل لوحة تحكم Supabase، نفّذ ملفات الهجرة بالترتيب:

1. `supabase/migrations/0001_schema.sql`
2. `supabase/migrations/0002_rls.sql`
3. `supabase/migrations/0003_views.sql`
4. `supabase/migrations/0004_servant_summary_view.sql`
5. `supabase/migrations/0005_seed_prayer_content.sql`
6. `supabase/migrations/0006_content_management_rls.sql`
7. `supabase/migrations/0007_seed_bible_books.sql`
8. `supabase/migrations/0008_qr_symposium_quizzes.sql`
9. `supabase/migrations/0009_quiz_staff_visibility.sql`
10. `supabase/migrations/0010_delete_attendance_sheets.sql`
11. `supabase/migrations/0011_content_open_to_staff.sql`
12. `supabase/migrations/0012_child_summary_extra_columns.sql`
13. `supabase/migrations/0013_notifications_fixes.sql`

(أو باستخدام Supabase CLI: `supabase db push` بعد ربط المشروع محليًا)

### 5) إنشاء المدير العام الأول

النظام يمنع إنشاء أكثر من مدير عام واحد، لذلك يُنشأ الأول عبر سكريبت مباشر
(وليس من الواجهة، لأن الواجهة نفسها تتطلب تسجيل دخول بمدير عام موجود بالفعل):

```bash
node --env-file=.env.local scripts/create-super-admin.mjs "اسمك الكامل" "01012345678" "كلمة-مرور-قوية"
```

### 6) تشغيل المشروع

```bash
npm run dev
```

افتح `http://localhost:3000` وسجّل الدخول برقم هاتف وكلمة مرور المدير العام
اللذين أدخلتهما في الخطوة السابقة.

> ملاحظة: عند البناء (`npm run build`) يحمّل المشروع خط "Tajawal" من Google
> Fonts تلقائيًا عبر `next/font/google`. إذا كنت تبني المشروع داخل بيئة معزولة
> بدون اتصال إنترنت، سيفشل البناء لهذا السبب فقط — الأمر يعمل بشكل طبيعي على
> Vercel أو أي بيئة لها اتصال بالإنترنت.

### 7) تشغيل الاختبارات

```bash
npm run test
```

راجع أيضًا `supabase/tests/rls_manual_test_plan.sql` لخطة اختبار يدوية لسياسات
الحماية على مستوى قاعدة البيانات — **يجب تنفيذها فعليًا قبل أي نشر حقيقي**، لأن
حماية بيانات الأولاد تعتمد بالكامل على صحة هذه السياسات.

## النشر على بيئة الإنتاج

### قاعدة البيانات (Supabase)
استخدم نفس مشروع Supabase أو أنشئ مشروعًا مخصصًا للإنتاج، وطبّق نفس هجرات
`supabase/migrations/` عليه بنفس الترتيب.

### التطبيق (Vercel)
1. ارفع الكود إلى مستودع Git (GitHub/GitLab).
2. من [vercel.com](https://vercel.com) استورد المستودع.
3. أضف نفس متغيرات البيئة الثلاثة من `.env.local` في إعدادات المشروع على Vercel
   (**Settings → Environment Variables**) — ولا تضع مفتاح `SUPABASE_SERVICE_ROLE_KEY`
   إلا في هذا المكان السرّي، أبدًا داخل الكود أو في متغيرات تبدأ بـ `NEXT_PUBLIC_`.
4. اضغط Deploy.

### الإشعارات الفورية (Web Push) — مرحلة قادمة
عند بناء قسم الإشعارات في المرحلة الرابعة، ستحتاج إلى توليد مفاتيح VAPID
(عبر `npx web-push generate-vapid-keys`) ووضعها في متغيرات البيئة
`NEXT_PUBLIC_VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY`.

## هيكل المشروع

```
app/                    صفحات Next.js (App Router)
  login/                تسجيل الدخول
  admin/                لوحة الإدارة (مدير عام / أمين عام / أمين خدمة)
  servant/              لوحة الخادم
  child/                لوحة الولد (المستخدم العادي)
components/             مكونات واجهة مشتركة
lib/                    دوال مساعدة (Supabase، الأدوار، تنسيق التواريخ...)
types/database.ts       أنواع TypeScript مطابقة لقاعدة البيانات
supabase/migrations/    هجرات قاعدة البيانات بالترتيب
supabase/tests/         خطة اختبار سياسات الحماية
scripts/                سكريبتات صيانة (إنشاء المدير العام الأول)
tests/                  اختبارات الوحدة
```

## ملاحظات أمان مهمة

- **لا تعتمد على الواجهة وحدها أبدًا لإخفاء البيانات**: كل صلاحية مطبَّقة أيضًا
  كسياسة RLS في قاعدة البيانات نفسها. حتى لو استُدعيت واجهة برمجية مباشرة
  بمعرفة توكن مستخدم عادي، لن يستطيع رؤية بيانات خارج نطاقه.
- **بيانات الاعتراف** مقيّدة بشدة: لا يراها إلا صاحبها أو المدير العام/الأمين
  العام، حتى الخادم وأمين الخدمة لا يستطيعان رؤيتها، تنفيذًا صارمًا لحساسية
  هذه البيانات.
- **رمز QR** يُعرض من صفحة "حسابي" (`/child/account` أو `/servant/qr`) ويُنشأ
  محليًا في المتصفح من `qr_token` — لا يمر عبر أي خادم خارجي.
- **مسح الرمز بالكاميرا** يحتاج اتصال HTTPS فعليًا (أو `localhost`)؛ لن تعمل
  الكاميرا على IP محلي عبر HTTP عادي — هذا قيد من المتصفح نفسه وليس من التطبيق.
- **ملفات المسابقات** (الصور وPDF) تُخزَّن في حاوية Supabase Storage خاصة
  `quiz-files` (غير عامة)، ويتم رفعها وتنزيلها فقط عبر روابط موقّعة صالحة لمدة
  قصيرة يُنشئها الخادم بعد التحقق من الصلاحية — لا وصول مباشر للملفات بدون ذلك.
- **رمز الاستجابة السريعة** لكل ولد (`qr_token` في جدول `profiles`) هو رمز
  عشوائي آمن (18 بايت) لا يحمل أي معلومة يمكن استنتاج هوية أو بيانات المستخدم
  منها.
- **درجة النشاط ودرجة الإكمال** في الصلاة وقراءة الكتاب المقدس مؤشرات تقريبية
  فقط، وليست إثباتًا قاطعًا لحدوث الصلاة أو القراءة فعليًا — هذا مقصود ومكتوب
  بوضوح في كل مكان يظهر فيه هذا المصطلح بالتطبيق.
- **`SUPABASE_SERVICE_ROLE_KEY`** يتجاوز كل سياسات RLS بالكامل، ويُستخدم فقط
  داخل Server Actions بعد التحقق اليدوي من صلاحية المستخدم الحالي أولًا
  (راجع `requireSuperAdmin()` في `app/admin/users/actions.ts` كمثال).

## المراحل القادمة

راجع خطة التطوير الأصلية (34 قسمًا) للتفاصيل الكاملة. تم إنجاز كل المراحل
الأساسية المخطط لها (الصلاة، القراءة، الحضور، صندوق الندوة، المسابقات،
الإشعارات، ولوحة متابعة الخادم الموسّعة). لا توجد صفحة "تقارير" في النطاق
الحالي للتطبيق — تمت إزالتها عمدًا بناءً على طلب صاحب المشروع.
